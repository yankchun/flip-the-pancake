# Delivery Traceability

Use this skill whenever a change crosses delivery phases or a handoff needs to be audited. Use `project-state` to keep the durable current-stage and handoff summary current. Do not create duplicate tracking artifacts when the existing project documents can be updated directly.

Keep requirement and story IDs stable across the discovery brief, delivery plan, architecture decisions, test plan, defects, and release plan. For each handoff, name the exact artifact or story, its status, supporting evidence, dependencies, unresolved questions, and next owner.

Before a release recommendation, check that accepted stories trace to verified acceptance criteria, material technical decisions are recorded, outstanding defects have a disposition, and risks are either mitigated or explicitly accepted by the appropriate decision-maker.
