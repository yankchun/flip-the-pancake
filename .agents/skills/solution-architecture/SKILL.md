# Solution Architecture

Use this skill for Solution Architect work when a change spans components, data, APIs, integrations, or material quality attributes. Do not use it for isolated implementation details that existing patterns already resolve.

Design the smallest viable architecture that meets approved requirements. Define component boundaries, data ownership, contracts, authentication and authorization boundaries, integrations, failure handling, observability, migration or compatibility needs, and relevant performance, reliability, privacy, accessibility, and security constraints.

Evaluate technology choices only when a decision is needed. Compare a recommended approach with meaningful alternatives against requirements, team capability, security, maintainability, cost, licensing, vendor lock-in, and migration effort. Do not commit the project to a paid tool, vendor, or external account without user approval.

Write or update `projects/<project-name>/03-architecture.md` from `templates/03-architecture.md`. Record decisions, alternatives, consequences, risks, and an implementation order. Hand implementation-ready boundaries and contracts to the appropriate developer roles; surface unresolved trade-offs to the user.
